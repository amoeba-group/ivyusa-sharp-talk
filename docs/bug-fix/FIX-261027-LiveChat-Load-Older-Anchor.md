# FIX-261027 — 라이브챗: '이전 대화 더보기'가 보던 위치를 잃고 맨 위로 튐

## 증상 (2026-10-27 사용자 요청)
대화방에서 [이전 대화 더보기]를 누르면 새로 불러온 묶음의 **맨 위(가장 오래된 메시지)**가 보인다. 보던 메시지 바로 위(통합 대화방이면 이전 세션의 마지막 대화)를 보려면 다시 한참 내려와야 한다.

## 원인
- `loadOlder`는 이전 30건을 `older` 앞에 붙이기만 하고 스크롤 위치는 손대지 않는다.
- 사용자는 버튼을 누르려고 맨 위(`scrollTop≈0`)에 있으므로, 위에 내용이 붙어도 `scrollTop`은 0 그대로다. 그래서 화면은 새로 붙은 맨 위 내용을 보여준다.
- PLN-261027 S1(D4)에서 "이전 대화 더보기는 위치를 바꾸지 않는다"고 했는데, 실제로는 '스크롤 값을 바꾸지 않는' 것이었고 '보던 메시지를 유지'하지는 않았다.

## 수정
`apps/web/src/domain/live-chat/LiveChatPage.tsx`
- 불러오기 직전에 대화 영역의 `scrollHeight`·`scrollTop`을 기억한다(`olderAnchorRef`).
- `older`가 바뀐 직후(`useLayoutEffect`, 그리기 전)에 `scrollTop = 새 scrollHeight − 이전 scrollHeight + 이전 scrollTop`으로 맞춘다. 위에 붙은 높이만큼 내려가므로 보던 메시지가 제자리에 있고, 바로 위에 직전 메시지가 이어진다.
- 검색 결과로 이동하는 경로(`revealMessage`)는 그 메시지로 스크롤하므로 기준점을 쓰지 않는다.

## 검증 (로컬)
대화 26에 임시 메시지 40건(총 42건) → 맨 위에서 [이전 대화 더보기].
- 수정 후: 보던 첫 메시지(msg 11)가 화면 같은 위치에 남고(위치 차이는 날짜 구분선 높이 정도), 바로 위에 msg 10이 보인다. `scrollTop` 0 → 1214.
- web tsc 통과. 임시 메시지는 삭제했다.

## 재발 방지 패턴
목록 **앞에** 항목을 붙이는 무한 스크롤·더보기는 반드시 '추가된 높이만큼 스크롤 보정'을 짝으로 둔다. "스크롤 값을 안 바꾼다"는 "보던 위치를 유지한다"가 아니다. 보정은 그리기 전(`useLayoutEffect`)에 해야 깜박임이 없다.

# REQ-261026 — 웹사이트 정책 분석 진행 히스토리

- 요청일: 2026-10-26
- 요청: "분석 진행 히스토리를 남겨서 진행 여부를 확인할 수 있도록 조치"
- 선행: REQ/PLN/RPT-261026-Site-Policy-Agent (#745, 스테이징·프로덕션 배포 완료)

## 1. AS-IS

| 항목 | 현황 | 근거 |
|---|---|---|
| 작업 저장 | **메모리에 테넌트당 1건**만 둠. 새 분석을 시작하면 이전 작업을 덮어씀 | `knowledge-ingest-job.service.ts` `Map<tenantId, IngestJob>` |
| 보존 기간 | 끝난 작업은 **1시간 뒤 사라짐**(`RESULT_TTL_MS`). API 재시작(배포)이면 즉시 사라짐 | 같은 파일 |
| 초안 | 승인 전 초안은 메모리에만 있음(의도된 설계: "승인 전엔 지식 아님") | PLN-260829 D4-1 |
| 감사 기록 | **보드 게시(승인) 때 1건만** 남음(`knowledge.site_ingested`). 시작·실패·방치는 기록 없음 | `approve()` |
| 화면 | 카드에는 "지금 진행 중 / 검수 대기" 1줄만 보임. 과거 실행은 볼 곳이 없음 | `SitePolicyAgent.tsx` |

따라서 지금은 다음 질문에 답할 수 없습니다.
- 어제 누가 어느 사이트를 분석했나?
- 그 분석은 끝났나, 실패했나, 게시됐나?
- 실패했다면 어느 페이지가 왜 실패했나?
- 초안이 게시되지 않고 사라졌나?

## 2. TO-BE

1. 분석의 **시작·완료/실패·게시**가 매번 영구 기록됩니다(누가·언제·어느 사이트·어느 페이지·결과).
2. 카드 아래 **"최근 분석"** 목록에서 실행마다 상태를 한눈에 봅니다.
   - 상태: 진행 중 · 검수 대기 · 게시 완료 · 미게시(검수 시간 만료) · 실패 · 중단(서버 재시작)
3. 행을 열면 **상세**가 나옵니다: 시작→완료→게시 타임라인, 페이지별 결과(초안 수 / 본문 부족 / robots / 오류 사유), 게시된 보드 문서 링크.
4. 진행 중이거나 검수 대기인 실행은 상세에서 바로 진행 화면이나 검수 화면으로 이어집니다.

## 3. 갭

| # | 갭 | 필요한 것 |
|---|---|---|
| G1 | 시작·완료·실패 기록 없음 | 작업 수명주기 이벤트를 영구 저장(작업 id로 묶음) |
| G2 | 시작한 사람 모름 | `startSite`에 실행자 전달 |
| G3 | 게시 기록과 실행 연결 없음 | 게시 감사에 작업 id 포함 |

| G5 | 화면 없음 | 이력 조회 API + 카드 목록 + 상세 모달 |

## 4. 제약

- 테넌트 범위 엄수(`tenant_id`). 권한은 분석 기능과 같은 `KNOWLEDGE_SOURCE_MANAGE`(master/director).
- 초안 본문은 이력에 남기지 않습니다(승인 전 = 지식 아님 원칙, 용량). 남기는 것은 건수·제목 수준 메타데이터뿐입니다.
- 이력 기록에 실패해도 분석 자체는 계속됩니다(기존 감사 기록과 같은 fail-open).
- 이 기능 이전(10/26 배포분)의 실행은 게시 감사 1건만 있으므로, 그 실행들은 "게시 완료"로만 보입니다(소급 불가 — 화면에 고지).

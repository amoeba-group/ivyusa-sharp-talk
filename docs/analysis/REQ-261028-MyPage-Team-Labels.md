# REQ-261028: 마이페이지에 지정된 팀과 업무 라벨 표시

- 요청일: 2026-10-28
- 요구사항 원문: "https://shoptalk.amoeba.site/my-page 마이페이지에 지정된 팀과 라벨도 표시 - (팀과 업무라벨은 마스터만 수정가능 안내)"

## 1. AS-IS
- 마이페이지 프로필 카드(`apps/web/src/domain/my-page/MyPage.tsx`)
  - **팀(unit)이 없다.** `users.unit_id`(PLN-261019, 1인 1팀)가 지정돼 있어도 본인은 볼 곳이 없다.
  - **업무 라벨**은 로그인 토큰(principal)의 `labels`, 즉 **코드**(`consult`, `accounting`, `operations`)를 그대로 보여준다. 테넌트가 바꾼 표시 이름(예: "상담", "Go2Joy CS")이 아니다.
  - 토큰 값이라 로그인 뒤에 마스터가 라벨을 바꿔도 다시 로그인할 때까지 옛 값이 보인다.
  - 라벨이 없으면 줄 자체가 사라진다.
  - 누가 바꿀 수 있는지 안내가 없다.
- 팀·라벨 변경 권한(`PATCH /users/:id/unit`, `/users/:id/labels`)은 capability `label.assign`이다. 현재 권한 매트릭스에서는 **master, director, manager**가 가지고 있다. 원문의 "마스터만 수정 가능"과 실제 권한이 다르다(PLN D2).
- `GET /users/me/profile`(PLN-261028 Agent-Profile-Avatar)은 이메일, 표시 이름, 아이콘만 돌려준다.

## 2. TO-BE
1. 마이페이지 프로필 카드에 **팀**과 **업무 라벨**을 테넌트가 정한 **이름**으로 보여준다.
   - 값이 없으면 줄을 숨기지 않고 "미지정"이나 "없음"으로 표시한다.
2. 두 항목 아래에 **읽기 전용 안내**를 둔다. 문구는 "팀과 업무 라벨은 마스터가 지정합니다…"(PLN D2).
3. 값은 서버에서 매번 읽는다. 토큰이 오래돼도 최신 상태가 보인다.

## 3. 갭
| # | 갭 | 조치 |
|---|---|---|
| G1 | 프로필 응답에 팀·라벨 없음 | `GET /users/me/profile`에 `unit {id, name}`와 `labels [{code, name}]` 추가 |
| G2 | 라벨이 코드로 표시됨 | 응답의 이름으로 표시 |
| G3 | 수정 권한 안내 없음 | 안내 문구 추가 |
| G4 | 안내("마스터만")와 실제 권한(master·director·manager) 불일치 | PLN D2에서 결정 |

## 4. 사용자 흐름
1. 상담원이 마이페이지를 연다.
2. 프로필 카드에 팀 "CS 1팀", 업무 라벨 [상담] [회계]가 보이고, 그 아래에 "ⓘ 팀과 업무 라벨은 마스터가 지정합니다. 변경이 필요하면 마스터에게 요청하세요."가 보인다.
3. 팀이나 라벨을 바꿀 수 있는 사람에게는 안내 옆에 [사용자 관리에서 변경] 링크가 보인다(PLN D3).

## 5. 제약
- 시스템 관리자(admin)에게는 팀·라벨이 없으므로 지금처럼 숨긴다.
- 스키마 변경은 없다.

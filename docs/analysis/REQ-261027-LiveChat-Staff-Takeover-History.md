# REQ-261027 — 라이브챗: 사람 상담원 대응 이력 · AI 자동응답 끄기/넘기기

## 요구사항 (2026-10-27)
- R1 상담 히스토리에 AI 에이전트가 아닌 **사람 상담원의 대응 이력이 빠져 있다.** 전체 히스토리(통합 대화방, 대화 25건)에 호출된 상담원, 배정된 상담원, 개입한 상담원이 **아이디(이름)**으로 표시되어야 한다.
- R2 상담원 호출로 사람 상담원이 대응할 때 **AI 에이전트 자동응답 끄기** 버튼이 필요하다.
- R3 배정 수락이 아니어도 매니저나 다른 상담원이 대응할 때 자동응답을 끄고, **답변을 마친 뒤 에이전트에게 넘기는** 버튼이 필요하다.

- 상담원들은 **수락(배정) 없이 바로 답장**한다. 담당 이력은 배정 행(`assignments`)과 알람으로만 만들어서, 직접 답장한 상담원(21, 61)이 이력에 없다.
- 연결 요청 알람은 '상담원 연결 요청(사유)'로만 보인다. **호출 대상(28, 29)과 알람을 확인한 상담원(21, 61)**은 이름이 표시되지 않는다.
- 이름 표시는 `staffDisplayName`(이름이 있으면 이름, 없으면 이메일 앞부분)이다. 로그인 아이디와 이름을 함께 보여주지 않는다.
- 상담원이 답장을 보내도 대화 상태는 `ai_active` 그대로이고, **AI가 계속 자동응답한다**(대화 938). 자동응답 설정 드롭다운(세션 단위: 채널 기본/자동/승인/끔)은 헤더에 작게 있지만, 상담원이 대응을 시작했다는 맥락의 버튼이 아니다.
- **[AI로 반환]은 수락해서 `status=agent`인 대화에서만** 보이고 동작한다(그 외에는 409). 수락 없이 대응한 상담원은 AI에게 돌려줄 버튼이 없다.
- 자동응답 설정 변경은 감사 로그 `agent.session.auto_reply`(target `session:{id}`, metadata conversationId·mode)로 남는다.

## 제약
- 고객에게 보이는 안내는 기존 핸드백 안내 문구(AI 설정에서 변경 가능)를 재사용한다.
- 배정·수락 규칙(최대 동시 상담, 담당자 표시)은 바꾸지 않는다. '수락'과 '직접 대응'은 구분해서 기록한다.
- 상담원 아이디는 테넌트 내부 콘솔에만 표시한다(위젯 표시명 불변).

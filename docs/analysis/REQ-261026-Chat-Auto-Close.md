## 2. AS-IS (코드·스테이징 조사)

### 2.1 대화 종료

대화 상태: `ai_active`(AI 응대) → `waiting`(상담원 대기) → `agent`(상담원 응대) → `ended`.

| 경로 | 위치 | 대상 | 동작 |
|---|---|---|---|
| 고객 "상담 종료" | 위젯 고지 줄 → `POST /chat/end` | 열린 대화 | 종료 + 배정 해제. 감사 로그 없음 |
| 상담원 종료 | 콘솔 `agent.service.ts` `end()` | 전부 | 종료, 감사 `agent.conversation_ended` |
| 방치 자동 종료 | `idle-conversation.service.ts` (30초 순회) | **`waiting`·`agent`만** | 양측 30분 침묵 → "더 도와드릴 일?"(`idle_prompt_at` 래치) → 60초 → "만족하셨나요?" + 종료 → 위젯 만족도 카드. 7일 경과분 무음 종료. 이메일 회신 약속·메신저 채널 제외 |

- 임계값은 전역 env(`IDLE_PROMPT_AFTER_MIN=30`, `IDLE_CLOSE_AFTER_SEC=60`), 문구는 코드 고정(6개 언어), 테넌트 설정 없음.
- **AI 대화(`ai_active`)는 자동 종료 대상이 아니다** — 스테이징(10/26) go2joy 열린 AI 대화 **231건 전부** 마지막 메시지 10분 경과(마지막 발신자 AI 216건), ivyusa 125건.
- **만족도는 종료된 대화에서만 가능** — `POST /chat/rate`가 `status≠ended`면 409, 위젯 `CsatCard`도 `ended`에서만 렌더. 평가 제출 후 별도 인사·종료 동작 없음.

### 2.2 상담원 연결 대기

| 항목 | 현행 |
|---|---|
| 연결 요청 | `waiting` + `agent_alerts`(배정 규칙 대상자별, 없으면 broadcast) + 콘솔 알람 모달·알람센터(#732) + 메일 |
| 대기 중 AI | 아무도 수락 안 한 `waiting`(agentId NULL)에서는 **AI가 계속 답변**(FIX-260806 A1). 수락하면 `agent`, AI 침묵 |
| 재알림 | `agent-alert-reminder.service.ts`(PLN-261015 D4) — `handoff_config.reAlert { afterMinutes, escalateToUserIds }`: N분 미확인 + 여전히 `waiting`이면 원 대상자 메일 재발송 + 지정 리더(=매니저) 알람 행·메일. 대화당 1회(`reminded_at`). 60초 순회. 콘솔 `/settings/handoff` "미응답 재알림". **스테이징에서 켠 테넌트 없음** → **B1은 이미 구현돼 있음(설정만 하면 됨)** |
| 업무시간 외 | `handoff-router.service.ts`: `businessHours` 밖 + `offHours.email` 설정 시 상담원 호출 대신 `mode:'email'` → 업무시간 외 안내(`offHours.notice`, 편집 가능) 즉시 출력, 연락 이메일이 없으면 위젯 `ContactEmailCard`로 이메일만 수집(`customers.email`), 대화 `reply_channel='email'`(상담원 답장이 메일로 감). `offHours.email` 미설정이면 업무시간 외에도 그냥 상담원 호출 |

**B와의 차이**
- **수락 지연 시 고객 안내 없음** — 재알림은 상담원 쪽만 움직인다.
- **AI 복귀 개념 없음** — `waiting`은 상담원이 수락하거나 30분 방치 규칙이 끝낼 때까지 유지.
- **콜백 요청 없음** — 연락처 수집은 업무시간 외 이메일 1종뿐, **전화번호 수집·콜백 목록·처리 상태 없음**.
- 업무시간 외 안내는 요청 즉시 나가며 "3분 뒤"가 아님(상담원이 없으니 기다릴 이유가 없음).

### 2.3 저장소 현황
- `customers.phone`·`email` 컬럼 있음(AES-GCM 암호화, email은 blind index). 리드 생성 `customerService.createFromLead`(삭제 요청된 주소 거부, 동의 필수 경로 `saveContactEmail`).
- `inquiries` 테이블은 상태(open/answered)만 있어 콜백 용도로 부족.

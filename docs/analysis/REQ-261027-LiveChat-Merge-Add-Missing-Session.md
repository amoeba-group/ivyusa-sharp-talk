# REQ-261027 — 라이브챗: 통합 대화방에 누락 세션 추가 · 다른 IP 접속 기록

## 요구사항 (2026-10-27)
https://shoptalk.amoeba.site/live-chat, 테넌트 go2joy, ADMIN123 / Lá Hotel Quận 10
- R1 고객 세션 통합에서 누락된 세션을 추가하는 기능이 필요하다. 현재 세션 15개(대화 17개)가 통합되어 있는데, 같은 고객으로 보이는 Session 899가 빠져 있다.
- R2 대화방(세션)에서 통합 대화방에 추가하는 기능, 또는 통합 대화방에서 세션을 추가하는 기능.
- R3 접속 IP가 다른 경우 따로 기록한다(같은 사용자가 다른 곳에서 접속할 수 있음).

**추가 요청 (같은 날)**
- R4 대화방의 고객 말풍선에 고객명을 표시한다.
- R5 통합 대화방에서 같은 회사의 다른 스탭이 접속한 것을 구분할 수 있어야 한다.
- R6 스탭별로 대화를 나눠 보는 기능이 필요하다.

## 원인 조사 (스테이징 DB 읽기 전용, 10/27)
- 통합 방 1: 고객 518(`laquan10`), 기업 4(`hotel:4118`, Lá Hotel Quận 10), 자동 추가 켬, 멤버 15.
- `identity_attributes.user_id = laquan10`인 세션은 34개다. 그중 **대화가 있는 세션은 899를 빼고 모두** 대화에 고객·기업이 연결되어(filed) 방 1에 들어가 있다.
- 세션 22308(대화 899): `identity_level=claimed`, user_id `laquan10`, hotel_id `4118`. 그런데 **대화 899에는 customer_id·company_id가 없다**.
- 시각:

  | 시각 (UTC) | 일 |
  |---|---|
  | 06:41:06 | 세션 22308 생성 (게스트) |
  | 06:41:14 | 대화 899 시작 — 세션이 아직 로그인 전이라 연결 없이 생성 |
  | 07:12:39 | 대화 899 종료 |
  | 07:52:05 | 같은 세션에서 claimed 로그인(identify). `attributeOpenConversations`는 **진행 중인(open) 대화만** 연결 → 이미 끝난 899는 그대로 |

- 통합 판정(`MergedRoomService.identityOf`)은 세션 고객 + 대화 고객·기업만 보고, 세션의 identify 속성(user_id·hotel_id)은 보지 않는다. 그래서 899는 '게스트'로 판정되어 후보에도 없다(E5105).
- 수동으로 추가할 방법도 없다. 통합 다이얼로그는 판정된 후보만 보여주고, 서버도 후보가 아니면 거부한다(E5106).

## AS-IS (IP)
- `sessions.first_ip`/`last_ip`/`last_ip_at`는 있다(마스킹 표시, 원문은 감사되는 [보기]). 통합 대화방에서는 세션별 IP를 보여주지 않고, 다른 IP에서 접속했다는 기록도 없다.

## AS-IS (고객명·스탭)
- 고객 말풍선에는 라벨이 없다. 상담원·자동응답·자동 안내만 라벨이 있다.
- 기업 기준 통합 방은 같은 호텔의 여러 스탭 계정을 한 방에 모은다. 스테이징 방 1(Lá Hotel Quận 10)에는 **`laquan10`(고객 518, 대화 14)과 `quanly003`(고객 593, 대화 5)** 두 스탭이 섞여 있는데, 대화창에서는 둘의 메시지가 똑같은 고객 말풍선으로 보인다. 세션 구분선에도 세션 번호와 채널만 있다.
- 대화 상세의 `mergedRoom.conversations[]`에는 대화별 고객 정보가 없다(id·세션·채널·상태·시각뿐).

## 제약
- 다른 고객의 세션이 섞이지 않게: 판정에 맞지 않는 세션을 수동으로 넣을 때는 운영자의 명시적 확인과 '수동 추가' 표시, 감사 기록이 필요하다.
- 테넌트 경계를 지킨다. 다른 방에 이미 있는 세션은 옮기지 않는다(먼저 그 방에서 빼야 함).
- IP는 마스킹해서 표시하고, 원문은 기존 감사 경로로만 본다.

# PLN-261028 — 상담원 응대 메시지 이름·아이콘 + 마이페이지 프로필 아이콘

- REQ: `docs/analysis/REQ-261028-Agent-Profile-Avatar.md`
- 상태: **승인됨 (2026-10-28, D1~D7 권장안)**
- UI 영향: 있음(콘솔 마이페이지, 위젯 상담원 말풍선, 콘솔 라이브챗 상담원 말풍선)
- 스키마 변경: **있음**. `users.avatar_asset_uuid` 칼럼 1개

## 결정 사항
| # | 결정 | 권장안 | 대안 |
|---|---|---|---|
| D1 | 아이콘 저장 | 테넌트 자산 저장소에 새 영역 `profile`(kind `avatar`)을 둔다. `users.avatar_asset_uuid`가 그 자산을 가리킨다. 업로드하면 서버가 가운데를 정사각형으로 잘라 **256×256 WebP**로 다시 인코딩한다(메타데이터 제거). PNG/JPG/WEBP를 받고 원본은 5MB까지. 교체하거나 지우면 이전 자산은 소프트 삭제 | 별도 테이블과 경로 |
| D2 | 위젯 이름 우선순위 | **상담원 표시 이름 > 테넌트 공통 호칭 > 표시 안 함**. 실명이 공통 호칭보다 우선한다. 이메일은 쓰지 않는다 | 둘 다 표시("Hoang Anh · Go2Joy Support") |
| D3 | 위젯 아이콘 우선순위 | **상담원 프로필 아이콘 > 테넌트 공통 상담원 아바타 > 기본 사람 아이콘** | 테넌트가 개인 아이콘 사용을 끌 수 있는 설정 추가 |
| D4 | 기본 디자인(아바타 줄 미사용) 테넌트 | 지금 말풍선 위에 있는 회색 이름 줄 앞에 **20px 원형 아이콘**을 붙인다. 프로필 아이콘이 있을 때만 붙고, 없으면 지금과 같다 | 아바타 줄 테넌트에만 적용 |
| D5 | 마이페이지 | 프로필 카드 맨 위에 아이콘(64px)과 [사진 올리기]·[삭제]를 두고, **표시 이름** 입력과 [저장]을 둔다. 모든 테넌트 사용자(직급 무관)가 **본인 것만** 바꿀 수 있다. 시스템 관리자(admin)에게는 숨긴다 | 사용자 관리 화면에서 마스터가 일괄 지정 |
| D6 | 콘솔 라이브챗 | 상담원 말풍선의 이름 옆에 같은 아이콘(20px)을 붙이고, 상단 사용자 메뉴에도 아이콘을 붙인다 | 위젯만 |
| D7 | 감사 | 아이콘과 표시 이름 변경을 `user.profile_updated`로 감사 기록한다 | 기록 안 함 |

## 단계
1. **SQL** `sql/261028-user-avatar.sql`: `ALTER TABLE users ADD COLUMN avatar_asset_uuid CHAR(36) NULL`. 배포 전에 먼저 적용하고 `migrations:manifest`를 갱신한다.
2. **API**
   - `TENANT_ASSET_AREA.PROFILE`과 kind `avatar`(정사각형으로 잘라 256 WebP로 변환, public)를 추가한다. 영역 할당량은 20MB이며 env로 바꿀 수 있다.
   - `UserProfileController`
     - `GET /users/me/profile`
     - `PATCH /users/me/profile`: `display_name`, 1~60자
     - `POST /users/me/avatar`: multipart
     - `DELETE /users/me/avatar`
     - 모두 `@Auth()`로 본인만, 테넌트 사용자만 허용한다.
   - 감사 기록 `user.profile_updated`를 남긴다.
   - `ChatService.resolveSenderNames`를 `resolveSenders`로 바꿔 `{name, avatar}`를 돌려준다.
   - `ChatMessageResponse.senderAvatar`를 추가한다(위젯 대화, 스레드, 이전 대화).
   - 콘솔 메시지 응답에도 `senderAvatar`를 추가한다.
3. **packages/types**: `senderAvatar?: { uuid: string; version: number } | null`.
4. **위젯** `MessageBubble`
   - D2의 이름 우선순위와 D3의 아이콘 우선순위를 적용한다.
   - 기본 디자인에는 D4의 20px 아이콘을 붙인다.
5. **콘솔**
   - 마이페이지 프로필 카드(W1): 업로드, 삭제, 표시 이름 저장, 성공·실패 토스트를 넣는다.
   - 라이브챗 말풍선과 상단 사용자 메뉴에 아이콘을 붙인다(W4).
   - i18n 6개 언어를 추가한다.
6. **테스트**
   - 단위: 업로드 검증(형식, 크기, SVG 거부), 정사각형 변환, 본인만 변경 가능, 이름 길이, 이름·아이콘 우선순위.
   - 로컬: 마이페이지에서 업로드하고 상담원으로 답장한 뒤 위젯 두 디자인에서 확인한다.
7. **배포**: SQL 선적용 → 스테이징 → 프로덕션(승인 후).

## 사이드 임팩트
| 영역 | 영향 |
|---|---|
| go2joy 위젯 | 표시 이름을 정한 상담원은 "Go2Joy Support" 대신 실명이 보인다(D2). 공통 호칭을 유지하려면 대안을 고른다 |
| 이미 보낸 메시지 | 이름과 아이콘은 응답할 때마다 조회하므로 과거 메시지도 새 이름과 아이콘으로 보인다 |
| 성능 | 메시지 목록당 사용자 조회는 지금과 같은 1회이고, 칼럼 하나가 늘어날 뿐이다 |
| 저장 용량 | 아이콘 1개는 수십 KB이며 사용자당 1개다(교체하면 이전 것은 소프트 삭제) |
| 개인정보 | 위젯에 나가는 것은 상담원이 직접 정한 이름과 사진뿐이다. 이메일은 노출하지 않는다 |
| 기존 화면 | 사용자 관리와 담당 이력은 지금처럼 `staffLabel`(아이디(이름))을 쓰고, 표시 이름이 그 "이름"이 된다 |

## 일정
구현과 검증 1일 → SQL 선적용 → 스테이징 → 프로덕션.

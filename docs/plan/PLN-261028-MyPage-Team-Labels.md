# PLN-261028 — 마이페이지 팀·업무 라벨 표시

- REQ: `docs/analysis/REQ-261028-MyPage-Team-Labels.md`
- 상태: **승인됨 (2026-10-28)** — 사용자 결정: "권한 그대로, 문구 삽입하지 않음" → D1·D4 채택, D2 권한 변경 없음 + 안내 문구 없음, D3(안내 옆 링크)도 안내 박스와 함께 제외
- UI 영향: 있음(콘솔 마이페이지 프로필 카드)
- 스키마 변경: 없음

## 결정 사항
| # | 결정 | 권장안 | 대안 |
|---|---|---|---|
| D1 | 데이터 | `GET /users/me/profile`에 `unit: {id, name} \| null`과 `labels: [{code, name}]`를 추가한다. 서버에서 매번 읽으므로 로그인 토큰의 `labels` 코드에 기대지 않는다 | 토큰 값 그대로 표시 |
| D2 | 안내 문구와 실제 권한 | **권한은 지금 그대로 두고**, 문구는 요청 취지에 맞춰 "팀과 업무 라벨은 **마스터가 지정합니다**. 변경이 필요하면 마스터에게 요청하세요."로 한다. 마스터에게 요청하라는 안내라서 사실과 어긋나지 않는다 | 문구를 "마스터만 수정할 수 있습니다"로 하고 `label.assign`을 **master만** 갖도록 바꾼다(director·manager는 지금 팀·라벨을 바꿀 수 있는데 그 권한이 사라짐) |
| D3 | 변경 권한이 있는 사람 | `label.assign`을 가진 사람(지금은 master·director·manager)에게는 안내 옆에 [사용자 관리에서 변경 →] 링크(`/users`)를 보여준다. 마이페이지에서 직접 편집하지는 않는다 | 링크 없음 |
| D4 | 빈 값 | 팀이 없으면 "미지정", 라벨이 없으면 "없음"(회색)으로 표시하고 줄은 숨기지 않는다 | 지금처럼 숨김 |

## 단계
1. **API**: `UserProfileService.get`에서 사용자의 `unit_id`에 해당하는 unit과 `user_job_labels`→`job_labels`를 같은 테넌트로 한정해 읽는다. `MyProfileResponse`에 `unit`과 `labels`를 추가한다.
2. **콘솔**
   - 프로필 카드의 라벨 줄을 응답 기반으로 바꾼다.
   - 팀 줄을 추가한다(안내 문구·링크 없음 — 승인 결정).
   - i18n 6개 언어.
3. **테스트**
   - 단위: 팀·라벨 이름 반환, 팀 없음·라벨 없음, 다른 테넌트의 unit·label 제외.
   - 로컬 화면: 팀·라벨 이름 표시, 빈 값 표시.
4. **배포**: 스테이징 → 프로덕션(요청 시). SQL 없음.

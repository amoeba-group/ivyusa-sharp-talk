## 결정 사항
| # | 결정 | 권장안 | 대안 |
|---|---|---|---|
| D1 | 말풍선 색 | 고객 = **흰 배경 + 회색 테두리**(왼쪽), 자동응답 = **연초록 진하게(emerald-100) + 초록 테두리**(오른쪽), 상담원 = 진보라(유지), 자동 안내 = 연노랑(amber-50) 점선(오른쪽) | 고객 회색을 더 진하게(gray-200)만 |
| D2 | 콜백·피드백 표시 위치 | 대화 흐름 안, 해당 시각에 **가운데 정렬 이벤트 카드**로 표시. 콜백은 📞 요청 시각·채널·연락처(마스킹)·상태(요청됨/완료 by 누구/취소), 피드백은 ⭐ 별점·해결 여부·사유·의견 | 오른쪽 패널에만 표시 |
| D3 | 데이터 전달 | 대화 상세 응답(`GET agent/conversations/:id`)에 `callbacks[]`와 `feedback`을 추가. 통합 대화방이면 방 전체 대화의 것을 함께 준다 | 별도 API |
| D4 | 담당 이력 이벤트 추가 | `callback_requested`(채널), `callback_done`/`callback_canceled`(처리자·소요 시간), `feedback`(별점) | 콜백만 |
| D5 | 카드와 모달 | 카드는 **최근 6건 + [전체 히스토리 보기]**. 모달은 통합 대화방이면 **방 전체 대화**의 담당 이력과 **세션 통합 이벤트**(통합·세션 추가·자동 추가·빼기·해제·자동 추가 설정)를 시간순으로 보여주고, 종류 필터(전체/담당/콜백/피드백/세션 통합)를 둔다. 각 줄에 어느 세션의 일인지 표시 | 카드를 길게 펼치기 |
| D6 | 통합 이력 API | 새 `GET agent/conversations/:id/history`(방이 없으면 그 대화만). 세션 통합 이벤트는 `merged_room_sessions` + 감사 로그 `merged_room.*`(target `merged_room:{id}`)에서 만든다 | 감사 로그만 |

## 단계
1. **API**
   - `ConversationHandlersService`에 콜백·피드백 이벤트 추가(`callback_requests`, conversation `csat_*`).
   - `history(conversationId)`: 통합 대화방이면 방의 모든 대화 이벤트에 세션 라벨을 붙여 합치고, `merged_room_sessions` + 감사 `merged_room.*`로 통합 이벤트를 만든다.
   - 새 라우트 `GET agent/conversations/:id/history`.
   - 대화 상세 응답에 `callbacks[]`(연락처 마스킹)과 `feedback`.
2. **웹**
   - 말풍선 색 변경(D1).
   - 대화 흐름에 이벤트 카드 삽입(시각 기준 병합).
   - `HandlerHistoryCard` 최근 6건과 [전체 히스토리 보기].
   - 새 `HandlingHistoryModal`(필터 칩).
   - i18n 6개 언어.
3. **테스트**: 이벤트 병합 순서, 콜백 소요 시간, 피드백 이벤트, 방 단위 합치기·테넌트 필터, 통합 감사 이벤트 해석. 로컬 화면 확인.
4. **배포**: 스테이징 → 확인 → 프로덕션. 마이그레이션 없음.

## 사이드 임팩트
| 영역 | 영향 |
|---|---|
| 말풍선 색 | 고객 말풍선이 흰색으로 바뀐다. 매뉴얼 캡처 갱신 대상 |
| 하단 스크롤 | 이벤트 카드도 대화 영역 높이에 포함된다. 새 콜백·피드백도 '새 메시지'처럼 하단 추종 규칙을 따른다 |
| 대화 상세 응답 크기 | 콜백·피드백은 대화당 몇 건 수준이라 영향이 작다 |
| 개인정보 | 콜백 연락처는 마스킹하고, 원문 보기는 기존 감사 경로를 쓴다 |
| 권한 | 새 라우트는 기존 담당 이력과 같은 `CONVERSATION_HANDLE` 권한 |

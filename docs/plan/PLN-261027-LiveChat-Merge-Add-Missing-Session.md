# PLN-261027 — 라이브챗: 통합 대화방에 누락 세션 추가 · 다른 IP 접속 기록

- REQ: `docs/analysis/REQ-261027-LiveChat-Merge-Add-Missing-Session.md`
- 상태: **승인됨 (2026-10-27, D1~D9 권장안)**
- UI 영향: 있음 (통합 대화방 관리 모달, 통합 다이얼로그, 전체 히스토리)

| D1 | 근본 원인(G1) | 로그인(identify, 서명·claimed 모두) 시 그 **세션의 미연결 대화 전부**(진행 중 + 이미 종료, customer·company가 모두 비어 있는 것만)를 고객·기업에 연결한다. 이미 다른 고객에 연결된 대화는 건드리지 않는다. 연결 후 자동 추가가 켜진 방이 있으면 바로 합류시킨다 | 진행 중만 유지 |

## 단계
1. **API**
   - identify(서명·claimed)에서 세션의 미연결 대화를 모두 연결하고(D1), 연결 후 `autoJoin`을 부른다.
   - `MergedRoomService.identityOf`에 세션 identify 속성 판정을 추가한다(D3).
   - `POST merged-rooms/:id/sessions` `{conversation_id, force?}`(D4①): 판정 → 미일치면 `force` 없이 409 E5107(확인 필요). 다른 방이면 E5106에 그 방 정보를 담는다.
   - `GET conversations/:id/room-options`(D4②): 같은 고객·기업 방 목록.
   - 방 응답의 세션 행에 마스킹 IP·`ipDiffers`·`manual`을 추가한다. 히스토리에 `session_ip_changed` 이벤트(D6).
   - 대화 상세: `mergedRoom.conversations[]`와 단일 대화에 고객(`customerId`·이름·역할)을 추가(D7·D8). `staff` 쿼리로 방 대화 범위를 그 고객 대화로 좁힌다(D9).
2. **SQL 백필**(D2): 대상 건수 조회 → 연결 UPDATE → 자동 추가 방 합류 INSERT. 롤백용으로 변경 대상 id를 별도 테이블 없이 SQL 주석의 확인 쿼리로 남긴다.
3. **웹**: 관리 모달 [세션 추가] + 확인 단계, 헤더 [통합 대화방에 추가] 팝오버, 세션 행 IP·배지, 히스토리 이벤트 문구, 고객 말풍선 라벨·스탭 색, 스탭 칩(선택 시 범위 재조회·더보기·하단 이동 초기화), i18n 6개 언어.
4. **테스트**: 종료된 대화 연결(D1), 이미 다른 고객인 대화는 불변, identify 속성 판정, 수동 추가(일치·미일치 force·다른 방·뺀 세션), IP 다름 판정, 테넌트 경계. 로컬 화면 확인.
5. **배포**: 스테이징 SQL 백필(대상 확인 후) → 코드 → 899가 방 1에 들어갔는지 확인 → 프로덕션(승인 후).

## 사이드 임팩트
| 영역 | 영향 |
|---|---|
| identify | 종료된 대화도 연결되므로, 그 대화가 고객 이력·대화 이력의 고객명·기업 이전 대화에 새로 잡힌다(의도된 효과) |
| 자동 추가 | 백필과 D1로 기존 방에 세션이 늘어난다. 운영자는 [빼기]로 되돌릴 수 있다(excluded는 다시 자동 추가 안 됨) |
| 오통합 위험 | 수동 추가는 판정 밖 세션도 넣을 수 있다 → 확인 단계, '수동' 배지, 감사 기록으로 추적 |
| 개인정보 | IP는 마스킹만 표시. 원문은 기존 감사 경로 |
| 성능 | 방 세션 목록에 IP 조회가 붙는다(세션 수십 개 수준, 1쿼리). 고객명은 방 대화의 고객 id를 한 번에 조회 |
| 찾기·답장 | 스탭 보기 중에도 [찾기]는 보이는 범위에서만, 답장 대상은 현재 대화 그대로. 스탭 칩을 바꾸면 찾기 결과를 초기화 |

## 단계
### S1 라이브챗 대화 영역 (R1·R2·R3) — 스키마 변경 없음
- API: `displayName(user)`(name → 이메일 @ 앞부분) 헬퍼를 user 모듈에 두고, `resolveSenderNames`·`agentName`·`analytics.agentNames`·`audit.actorName`이 함께 쓰게 한다. 메시지 응답에 AI 에이전트 이름(대화의 ai_agent)을 넣는다.
- 웹: 대화 영역 ref와 하단 이동(D4), "새 메시지 ↓" 버튼, 말풍선 3종 스타일과 라벨(D2·D3). 하드코딩된 "AI"를 i18n으로 바꾼다.
### S2 상담 담당 이력 (R4) — 스키마 변경 없음
- API: `GET agent/conversations/:id/handlers`(테넌트 필터, 라이브챗 메뉴 권한). 항목 = {at, kind: ai_start|handoff_request|assigned|transferred|handed_back|released|ended, agent, by, reason, type}. 수락 시 이전 active 배정 닫기(D6).
- 웹: `HandlerHistoryCard`를 오른쪽 패널 맨 위에 두고 5초 폴링 데이터와 함께 갱신한다.
### S3 대화 이력·작업로그 (R5·R8) — 스키마 변경 없음
- API: `searchConversations`의 고객명(D13)과 마지막 상담원(D14). 작업로그 행에 conversationId와 messageId를 함께 내려준다.
- 웹: 대화 이력 칸 이름 변경. 작업로그 대화 서랍(`ConversationTranscript` 재사용, 강조 messageId). `ConversationTranscript` 역할 라벨 보강(D7).
### S4 고객 탭·일반고객 상세·메모 (R6·R7 일부) — **스키마 변경**
- SQL `sql/261027-customer-memo.sql`: `customers.memo VARBINARY(8192) NULL`(암호화).
- API: `GET /customers/:id/detail`(최초 접속·유입·대화 50건·소속 기업), `PATCH /customers/:id`에 phone·email·memo 추가(감사 기록 `customer.updated`, 필드 이름만). DSAR에 memo 추가.
- 웹: 탭 2개(D8), `CustomerDetailModal`(D9), 목록에 최초 접속·대화 수 칸.
### S5 플랫폼별 최소 정보 (R7 나머지) — **스키마 변경**
- SQL `sql/261027-customer-platform-links.sql`: 새 테이블(D12).
- API: `CustomerService.linkPlatform(provider, externalId, displayName)`. Shopify·Cafe24·Woo·Haravan·Odoo 동기화와 embed identify 호출부에 연결. 기존 고객의 Shopify·Cafe24·외부 id는 백필 SQL로 채운다. DSAR 시 삭제한다.
- 웹: 상세 모달의 '연동 플랫폼' 탭.

## 사이드 임팩트
| 영역 | 영향 |
|---|---|
| 표시 이름 | 이름이 빈 상담원은 '상담원' 대신 이메일 앞부분이 고객 화면이 아닌 **콘솔에만** 보인다. 위젯의 상담원 표시명(`agent_sender_name_*`)은 바꾸지 않는다 |
| 말풍선 색 | 상담원·AI 색 의미가 바뀐다(AI 연보라 → 연초록). 매뉴얼 캡처 갱신 대상 |
| 자동 스크롤 | 찾기 결과 가운데 맞춤·이전 대화 더보기와 충돌하지 않게 조건을 분리한다 |
| 배정 이력 | 기존 배정 행은 그대로 둔다. 과거 수락 건은 active가 겹쳐 있을 수 있어, 이력에서는 시간순으로 표시하고 겹침은 이관으로 해석하지 않는다 |
| 대화 이력 정렬·필터 | 마지막 상담원 필터(`agent_id`)는 새 규칙의 COALESCE로 같이 바꾼다 |
| 고객 탭 링크 | 기업 카드(`HotelCard`)의 `?tab=b2b&company=` 링크는 유지 |
| 개인정보 | 메모·플랫폼 표시명은 DSAR 삭제 대상에 넣는다. 원문 연락처는 열람 경로에서만 보이고, 열람은 감사 기록을 남긴다 |
| 마이그레이션 | S4·S5는 스테이징·프로덕션 모두 SQL 선적용 후 배포(`pre-deploy-check`) |

## 일정(안)
S1 0.5일 → S2 0.5일 → S3 0.5일 → S4 1일 → S5 1일. 단계마다 스테이징에 배포하고, 프로덕션은 묶어서 반영한다.

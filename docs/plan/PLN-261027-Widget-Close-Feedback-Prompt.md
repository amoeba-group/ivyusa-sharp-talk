## 결정 사항
| # | 결정 | 권장안 | 대안 |
|---|---|---|---|
| D1 | 안내 조건 | X 클릭 시 **진행 중 대화(AI 응대 또는 상담원 응대)에 고객 메시지가 1개 이상**이고 아직 평가하지 않았으며 '앞으로 안 보기'를 누르지 않았을 때만 안내. 대기열(`waiting`)·대화 없음·종료됨이면 지금처럼 바로 닫음 | 모든 X 클릭에 안내 |
| D2 | 안내 형태 | 패널 안 하단 시트(오버레이)로 문구와 버튼 3개: **[피드백 남기기]**(주 버튼), [그냥 닫기], [앞으로 안 보기](텍스트 링크) | 브라우저 확인창 |
| D3 | 버튼 동작 | 피드백 남기기 = 상담 종료 → 대화 탭으로 이동해 기존 만족도 카드(테넌트 rating/survey) 표시, 패널 유지 / 그냥 닫기 = 상담 종료 + 닫기 / 앞으로 안 보기 = 저장 + 상담 종료 + 닫기 | 앞으로 안 보기는 종료 없이 닫기 |
| D4 | '앞으로 안 보기' 저장 | 위젯 출처의 localStorage(테넌트별 키). 브라우저 단위이며, 지워지면 다시 묻는다 | 고객 계정에 서버 저장 |
| D5 | 테넌트 설정 | `tenants.close_feedback_prompt`(기본 **켬**). 콘솔 **위젯 설정 > 노출 설정**에 "닫을 때 상담 피드백 안내" 토글. 세션 ensure 응답으로 위젯에 전달 | 설정 없이 전 테넌트 적용 |
| D6 | 범위 | 헤더 X만 가로챈다. 트리거 모드 데스크톱의 바깥 클릭·Esc(로더가 닫음)와 앱 모드 호스트 닫기는 지금 그대로 | Esc도 가로챔 |

## 단계
1. **SQL** `sql/261027-close-feedback-prompt.sql`: `ALTER TABLE tenants ADD COLUMN close_feedback_prompt TINYINT(1) NOT NULL DEFAULT 1`(배포 전 선적용).
2. **API**: 테넌트 엔티티·설정 DTO·응답, 위젯 ensure 응답에 `closeFeedbackPrompt`.
3. **위젯**:
   - 스토어에 `closeFeedbackPrompt`, 대화 탭이 "닫기 전 안내 필요 여부"를 스토어에 알림(진행 중·고객 메시지 있음·미평가).
   - `WidgetPanel.dismiss`가 조건이면 안내 시트를 띄운다.
   - 버튼별 동작(종료 API 재사용, 대화 탭 전환, localStorage).
   - i18n 6개 언어(문구: "상담피드백을 남기시면 서비스 개선에 도움이 됩니다." 등).
4. **콘솔**: 위젯 설정 토글, i18n.
5. **테스트**: 조건별 노출(진행 중/대기열/종료/평가 완료/안 보기/설정 끔), 버튼 3종 동작, 종료 후 만족도 카드 표시, 테넌트 설정 저장·전달. 로컬 위젯으로 확인.
6. **배포**: SQL 선적용 → 스테이징 → 프로덕션(승인 후).

## 사이드 임팩트
| 영역 | 영향 |
|---|---|
| 대화 종료 | X로 닫으면 상담이 종료된다(그냥 닫기·앞으로 안 보기·피드백). 지금은 X가 대화를 끝내지 않는다 → 상담원 응대 중 고객이 닫으면 대화가 끝난다. 대기열은 제외(D1) |
| 통계 | 고객이 직접 끝낸 대화가 늘고, 만족도 응답 수가 늘 것으로 예상 |
| 설정 끔 | 테넌트가 끄면 지금과 완전히 같다 |
| 개인정보 | 저장하는 것은 '안 보기' 플래그뿐(localStorage) |

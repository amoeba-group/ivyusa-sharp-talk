## 결정 사항

| # | 결정 | 권장안 | 대안 |

## 단계

### S1 — 스키마·설정 (SQL 1파일)
- `sql/261026-chat-close-callback.sql`: `tenants.chat_close_policy JSON NULL`, `callback_requests` 생성 + `npm run migrations:manifest`.
- 엔티티(`type` 명시, bigint transformer, 연락처 `secretTransformer`), `packages/types` `ChatClosePolicy`·`CallbackRequest` + 정규화.
- `HandoffConfig`에 `queueTimeout`·`callback`, 검증: `queueTimeout.afterMinutes > reAlert.afterMinutes`(재알림 켠 경우).
- 테넌트 편집 문구 저장 시 모더레이션 검사.
- 신규 오류 코드 E5114~(정책 범위, 콜백 꺼짐, 연락처 형식, 콜백 없음/타 테넌트).

### S2 — 만족도 요청 → 종료 (A1·A2)
- `idle-conversation.service.ts` 정책 테넌트 분기: `ai_active`·`agent`, 위젯 채널, `reply_channel` NULL.
  - 마지막 메시지 AI/상담원 + `csatAfterMin` 경과 + 래치 없음 → 만족도 요청 문구 + `idle_prompt_at` + 감사 `chat.csat_prompted`.
  - 래치 + `closeAfterMin` 경과, 그 뒤 고객 메시지 없음 → 종료 안내 → 종료(`chat.idle_closed`, `reason:'csat_timeout'`).
  - 정책 저장 이전에 멈춘 대화 → 무음 종료(231건 일괄 발송 방지).
- 정책 없는 테넌트는 현행 경로 그대로. 고객 새 메시지 → 래치 해제(현행).

### S3 — 진행 중 평가·감사 인사 (A3)
- `rate()`: `ended` 외에 래치가 있는 진행 중 대화 허용 → 저장 후 감사 문구 + 종료(`reason:'csat_submitted'`). survey 모드는 최종 제출 시.
- `chat.mapper.ts` `canRate` 같은 조건, 위젯 `ChatTab`은 `canRate`면 상태 무관 `CsatCard` 렌더.

### S4 — 연결 지연 → AI 복귀 (B1~B3)
- B1은 기존 재알림 그대로(go2joy 설정만).
- `agent-alert-reminder.service.ts` 순회 60초 → 15초, `queueTimeout` 처리 추가:
  `waiting` + agentId NULL + 첫 알람 후 N분 → 지연 안내(세션 언어, 모더레이션) → `ai_active` 복귀, 남은 `new` 알람 `expired`, 감사 `chat.queue_timeout`, 콜백 사용 시 응답에 `callbackOffer`.
- 업무시간 외(D4): 콜백 사용 테넌트는 `escalate`에서 안내 직후 같은 복귀 처리 + `callbackOffer`. 콜백 미사용은 현행.
- 콘솔 알람 모달·알람센터 사유/상태 문구에 `expired`·`callback_request` 매핑(#729 함정).

### S5 — 콜백 요청 (B4·B5)
- API(위젯, 세션 토큰):
  - `GET /chat/callback/options` — 콜백 사용 여부·받을 종류·회원 연락처 **마스킹 값**(verified 세션만; 평문은 위젯으로 내려가지 않음).
  - `POST /chat/callback { source: 'member' | 'entered', channel?, contact? }` — `member`는 서버가 회원 연락처를 직접 읽어 사본 저장, `entered`는 동의 게이트·형식 검증(이메일 / 전화 E.164 정규화)·suppression 거부. 대화당 열린 요청 1건(재요청=갱신), 확인 문구(마스킹), 알람+메일(D7). 회원정보·고객 프로필은 수정 안 함(D5).
- API(콘솔): 목록(`page`/`size`, 상태 필터, 마스킹) · 열람(감사) · 처리 완료/취소. 권한 `conversation.handle`, 테넌트 필터.
- 위젯 `CallbackCard.tsx`(기존 `ContactEmailCard` 패턴) — 회원 연락처 화면 ① / 입력 화면 ②(입력칸 기본 가림 + 👁 보기 토글, D10), 대화 응답의 `callbackOffer`로 버튼 노출.
- 콘솔 알람센터 탭 + 대화방 배너.
- DSAR 삭제 시 `callback_requests` 파생 삭제.

### S7 — 검증·배포
- 단위: 만족도 요청 조건(마지막=AI/상담원, waiting 제외), 래치 해제, 3분 종료, 평가→감사→종료, 정책 없음 무변경, 이메일·메신저 제외, 기존 대화 무음 종료 / 지연 안내 1회·수락 시 미발송·복귀·알람 expired / 업무시간 외 즉시 / 콜백 동의·형식·중복·테넌트 격리·마스킹, 회원 연락처(verified만, claimed·게스트는 입력), 응답에 평문 연락처 없음. 위젯: 입력칸 기본 가림·👁 토글·Chrome 비밀번호 저장 제안 미발생(`autocomplete` 함정 — Chrome은 password 칸의 off를 무시하므로 `new-password`/`one-time-code` 실측).
- 실측(스테이징 go2joy): A 흐름 2갈래, B 흐름(업무시간 내·외), 콜백 접수→알람·메일→처리 완료.
- SQL 스테이징→프로덕션 선적용 후 배포, PR `## Migration` 섹션. 진짜 부팅 확인(엔티티 변경).

## 영향 분석

| 영역 | 영향 |
|---|---|
| 기존 테넌트 | 정책·`queueTimeout`·`callback` 미설정 → 변화 없음(재알림 순회 주기만 15초) |
| 통계 | AI 대화가 실제로 종료돼 "진행 중" 감소, 만족도 표본 증가, 해결률·대기 시간 수치 변동 → RPT에 배포 컷오프 기록. 지연 복귀는 "상담원 미연결"로 집계 |
| 상담원 | 3분 뒤 알람이 `expired`로 사라짐 → 늦게 본 상담원은 콜백 탭에서 이어받음 |
| 업무시간 외 | 콜백 사용 시 `reply_channel='email'` 경로 대신 콜백으로 대체(D4) |
| 개인정보 | 전화번호 수집 신규 → 동의·암호화·마스킹·열람 감사·DSAR 삭제 |
| 모바일 SDK·Hotel Admin 앱 | 위젯 화면 동일 — 별도 작업 없음 |
| 메신저 채널 | 대상 아님 |
